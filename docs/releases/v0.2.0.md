# Līlāvatī 0.2.0 (alpha): release notes

*Release candidate, not yet tagged. Alpha software for research and teaching; not investment advice.*

```bash
pip install "lilavati-finance @ git+https://github.com/revendrat/lilavati@main"   # import name: lilavati
# once on PyPI: pip install lilavati-finance==0.2.0
```

## What this release is

Līlāvatī is a tool layer for AI agents in finance: deterministic engines for fixed income,
derivatives, econometrics, financial ML, execution and sustainable finance, served as eight MCP
servers that LangGraph, Google ADK, Claude and any MCP client can call, plus a benchmark that
measures what happens when language models compute in text instead. This release is about making
every number checkable.

## Highlights

**Engines checked against independent references.** Textbooks, original papers and QuantLib were
used to audit eight engines; 33 bugs were found and fixed, among them GARCH orders passed to `arch`
swapped, a Beneish coefficient with the wrong sign, a Merton solver that returned non-solutions for
distressed firms, and an Almgren-Chriss schedule with mixed units. Each audited engine has a
validation page with the reference used and the tolerance measured ([validation](../validation/index.md)).
Not yet audited: the order book, Black-Litterman and HRP engines, and the statement graph. The SEC
filing connectors had six bugs found and fixed on real filings ([connectors](../validation/connectors.md)).

**A benchmark with published evidence.** Every reply from every model run is in `results/`, with a
manifest (SHA-256, run settings, prompt version, content hash of each question), a generated
analysis with bootstrap confidence intervals, and a CC BY 4.0 data licence
([results](https://github.com/revendrat/lilavati/blob/main/results/ANALYSIS.md)). Failures are
classified as provider errors, model errors, truncation, unparsable replies or wrong answers, and
only provider errors are ever re-run.

**Tools versus no tools, on the same questions.** On 20 generated finance cases (prompt v3), four
open-weight models served by Groq were run without tools and with eight deterministic tools:

| Model | Item accuracy, no tools | With tools | Paired difference (95% CI) |
| :--- | ---: | ---: | :--- |
| Qwen3.6 27B | 0.7000 | 1.0000 | +0.3000 (+0.1000 to +0.5000) |
| Qwen3.8 27B | 0.3917 | 0.8000 | +0.4083 (+0.1125 to +0.6917) |
| gpt-oss-120b | 0.9375 | 0.9875 | +0.0500 (0.0000 to +0.1500) |
| gpt-oss-20b | 0.7000 | 0.7875 | +0.0875 (−0.2125 to +0.3750) |

Bootstrap bounds carry Monte Carlo error of about ±0.01. Tools helped the two Qwen models (intervals exclude zero); for the gpt-oss models the difference
is not distinguishable from zero at this sample size. Tools also introduced failure modes of their
own, which are measured and reported: malformed tool calls, tool-call loops, and a unit mismatch at
the tool boundary (a vega already per volatility point divided by 100 again). These are pilot-scale
results: one pass, 20 questions per model. Details: benchmark paper §5.3.

**Real filings.** SEC figures are now taken from the filing itself: identify the 10-K or 10-Q,
then keep only that filing's own XBRL facts, so prior-year comparatives are never returned as
current. Piloted on the latest 10-Ks of Apple, Microsoft, Walmart, J&J and JPMorgan: every
extracted value (71 of 71) appears in the filing document. Available as the MCP tool
`get_filing_figures`. [Tutorial 08](../tutorials/08_real_10k_llm_vs_lilavati.md) compares an LLM
alone, an LLM with Līlāvatī and Līlāvatī alone on four of those filings: the models read every line
item correctly (324 of 324); computing ratios themselves they got 225 of 228, against 228 of 228 when
code computed them.

**Checks that can fail, and citations that resolve.** Several "verified" flags could not fail: the
three-statement model, the 10-K PDF parser and the Ind AS crosswalk set `cash_reconciled=True`
without a check, and the investment committee derived equity and opening cash so that its identity
checks always held. Each now checks reported numbers only, lists what a filing does not report
instead of filling it, and refuses when a required item is missing. `ProvenanceGate(store)` resolves
every citation against the sources a pipeline actually read (`SourceStore`: tag, period, filing date,
page snippet, value). The research agent builds its dossier from one 10-K's reported figures, cited
and checked (live on Apple, Microsoft, Walmart and Nvidia). The Ind AS crosswalk was checked on Maruti
Suzuki's FY2025-26 results, line by line against the printed statements. Black-Litterman raises when
its solver fails instead of returning equal weights. Which library does what, and how to cite it:
[libraries, solvers and citations](../validation/libraries.md).

**Tutorials and a course.** Eight tutorials, each with objectives, runnable code, the real mistakes
it guards against, exercises and instructor notes; CI runs their code exactly as written. A draft
12-week course, *AI in Finance: Harnessing LLMs, Correcting Their Mistakes*, maps them to labs and
capstone projects ([course](../course/index.md)).

**Providers and integrations.** One client for OpenAI-compatible APIs (including Groq, Ollama and
vLLM), Gemini and Anthropic, with tool calling on all three and bounded retries. LangGraph, Google ADK
and A2A examples run end to end on a real model.

**Quality gates in CI.** Lint, type check and the test suite on Python 3.11 and 3.12; a strict docs build;
every example; every tutorial's code; a claims linter that rejects over-claiming language; and a check that the results manifest matches the files. Releases go through
PyPI Trusted Publishing after a clean-install smoke test.

## Breaking changes

- The distribution is now `lilavati-finance` (the name `lilavati` on PyPI belongs to another
  project). The import name is still `lilavati`.
- `ExecutionEngine.compute_almgren_chriss_schedule` and its MCP tool require the keyword argument
  `arrival_price`; impact parameters use the paper's per-day units.
- Generated benchmark case ids carry the seed and set size (`GEN-S2026-N4-T2-000`). Match results
  by `case_content_hash`, or resolve old ids with `lilavati.bench.generator.legacy_case_id`.
- Benchmark prompt helpers moved from `scripts/run_llm_baseline.py` into `lilavati.bench.llm_eval`.
- `AdversarialCommittee.evaluate_company` and the MCP tool `evaluate_investment_committee_memo`
  require `total_liabilities_t`, `shareholders_equity_t`, `retained_earnings_t`, `operating_income_t`,
  `cash_start_t` and `cash_end_t` (optional `fx_effect_on_cash_t`); the memo has `checks`.
- `FinancialResearchAgent.conduct_deep_research` raises `ValueError` when SEC cannot be reached or the
  10-K lacks an input (it used to fall back to an illustrative baseline); the dossier's
  `recommendation` is the committee's rule-based verdict, and it adds `filing`, `committee_memo`,
  `citations_verified`, `inputs_usd_millions` and `derived_inputs`.
- `ExecutionEngine.optimize_black_litterman` raises on invalid inputs and solver failure (it returned
  equal weights), and its result has a `solver` field.
- `IndiaFilingsClient.parse_ind_as_disclosure` returns `IndASParseResult` (statement model, cited
  facts, `derived`, `not_reported`, `checks`) instead of a tuple, and raises when a required item is
  not given. The cost-of-goods and tax keys follow Schedule III
  (`ChangesInInventoriesOfFinishedGoodsWorkInProgressAndStockInTrade`, `CurrentTax` + `DeferredTax`).

The full list of fixes is in the [changelog](https://github.com/revendrat/lilavati/blob/main/CHANGELOG.md).

## Known limitations

- **Not independently reviewed.** No outside practitioner or software review has taken place yet.
- **Engines not yet audited:** order book, Black-Litterman, HRP (#15, #16), statement graph,
  connectors. The statement graph no longer balances by an equity plug (fixed 2026-11-27), so its
  balance check can fail; it is checked against hand calculations, not a published worked example.
- **Data connectors.** SEC XBRL extraction is a five-company pilot (latest 10-Ks; one of them a bank,
  whose statements fit the canonical items poorly). In a 10-Q, cash-flow items are year-to-date and
  are listed as missing. The three-statement model (`get_company_filing_statements`) refuses filings
  that do not report operating income (J&J; banks). The 10-K PDF parser is checked on one filing
  (Apple FY2026) and the Ind AS crosswalk on one company's annual results (Maruti Suzuki FY2026);
  neither is validated beyond that.
- **Not implemented:** purged and embargoed cross-validation, and the other items listed under
  "Not yet implemented" in the roadmap.
- **Benchmark scale:** 7 golden cases (saturated for strong models) and 20 generated cases per
  model, one pass; generated cases cover 5 of the 7 tracks. Anthropic tool calling is format-tested
  only.
- **Z3 checks** verify the numbers given to them (exact rational arithmetic on concrete inputs);
  only `check_covenants_over_ranges` and the covenant-path functions decide properties over ranges of
  inputs, under their stated models (annual periods; no revolver, dividends or trailing-twelve-month
  EBITDA). The diagnosis of failed identities names candidate figures; it cannot say which source
  figure is right. Point-in-time queries limit what the store returns;
  detecting look-ahead use by an agent is partial.
- **The API server** has no built-in authentication and binds to `127.0.0.1` by default.

## Verifying this release

Each artifact is listed with its SHA-256 in `SHA256SUMS`. To reproduce the published analysis from
the stored replies, without API calls:

```bash
uv run python scripts/build_results_manifest.py --check
uv run python scripts/analyse_results.py
```
