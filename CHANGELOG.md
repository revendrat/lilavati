# Changelog

## [Unreleased]
These changes ship in 0.2.0 when it is tagged (the version in `pyproject.toml` is already 0.2.0).
### Added
- Pull request review in the daily routine (`lilavati-daily` section 1b): each day, before the goal, every open pull request from someone else is checked out in a scratch worktree, its new tests are run against `main` (a fix's tests must fail) and the branch (they must pass), the checks and the changed code's callers are run, a review listing what was checked and each finding (blocking or optional) is posted, and the pull request is merged when nothing is blocking and CI is green; dependency, workflow, packaging, evidence and out-of-scope changes go to the maintainer first. The contributing guide says how a pull request is reviewed.
- One goal per day: the `lilavati-daily` skill (open, pick, goal card, build, prove, close), `scripts/next_goal.py` (ranks the unblocked TODO items: due, then correctness, validation and phase order; flags items to split; lists open roadmap items with no TODO entry) and `scripts/check_all.py` (every check in one command, one line each; the paper check is reported, not failed). TODO.md items that wait on the maintainer, reviewers, budget, a key or a download now carry `*Blocked: <reason>.*`, deadlines `*Due: YYYY-MM-DD*`; a test checks that waiting items are marked. Contributing guides and CLAUDE.md list the two commands.
- `scripts/check_papers_current.py`: lists the dated ROADMAP and TODO milestones newer than each paper's version line, with the paper each concerns (`--strict` fails if a paper is behind); developer skill section 4c on revising the papers at each milestone. Tested.
- NSE Integrated Filing (Financial) reader (`connectors/nse_integrated_filing.py`): NSE's page for an Ind AS filing (rendered from XBRL filed against SEBI's `in-capmkt` taxonomy, version 2025-01-31), supplied by the user, read into the Ind AS crosswalk: sections and their columns (quarter, year to date, standalone or consolidated), Indian digit grouping, headings that separate repeated labels; nothing filled; every figure cited to the page's hash. On Maruti Suzuki's consolidated filing for the year ended 31 March 2026: 26 of 26 earlier manual readings and 26 of 28 printed items equal; the two differences (profit before tax excludes associates and joint ventures, 2,855; PP&E includes right-of-use assets, 5,998) reconcile to the unit; the three crosswalk identities hold. Tutorial 10. `scripts/check_tutorials.py` skips blocks that read files downloaded by hand into `data/raw/`.
- Documentation process (developer skill, section 4b) and a test that keeps it: every tutorial is in the docs navigation, the README table and count, the docs home, and the course schedule, and has the standard sections (`tests/test_docs_coverage.py`). Tutorial 09 gained "Where this fits", "What can go wrong", "Using this with Claude Code and MCP" and "For instructors"; use cases in the README now list the backtest statistics and the Indian filing reader.
- Backtest overfitting (`core/backtest_overfitting.py`, roadmap 7.4): purged and embargoed K-fold and combinatorial purged cross-validation with backtest paths (López de Prado 2018, ch. 7 and 12); the Probabilistic and Deflated Sharpe ratios (Bailey and López de Prado), with the expected maximum Sharpe ratio of the false strategy theorem; the probability of backtest overfitting by CSCV (Bailey, Borwein, López de Prado and Zhu 2017). The DSR reproduces the authors' worked example (SR₀ 0.1132, DSR 0.9004); PBO matches a direct transcription of Algorithm 2.3; the CV splits match an independent implementation of the definitions (not yet AFML's code). MCP tools `compute_deflated_sharpe_ratio` and `estimate_probability_of_backtest_overfitting` (32 tools). Tutorial 09: the best of 400 seasonal rules on a random walk has an annualised Sharpe ratio of 1.43 and a DSR of 0.010; PBO averages 0.50 on noise and 0.10 with a planted effect over 20 seeds; the DSR fails the planted effect when 400 correlated rules are counted as 400 independent trials.
- Real-model evaluation of the extraction workflow (`scripts/run_extraction_repair_eval.py`, raw replies in `results/extraction/`): five pilot 10-Ks, 60 figures, four open-weight models on Groq, four arms (one pass, targeted re-read, re-read everything, implied values shown) from a shared first reading. The first run (x1) found the quote-check and revenue-label faults listed under Fixed; after them (x2), 240 of 240 figures were correct in one pass at temperature 0. A probe at temperature 1.0 (two models, three samples) gave three quotes not in the document, all caught and fixed by one re-read, and one misreading the checks could not catch (JPMorgan's noninterest revenue for total net revenue; no identity involves a bank's revenue, so it is listed as `unchecked`). No identity failed, so the diagnosis-driven repair is not yet measured on real model output (`docs/agent-workflows.md`).
- Agent workflows. `FilingExtractionAgent` (`agents/extraction.py`): a model (or any callable) reads statement figures with the line each came from; the agent checks each quote is in the document and the value is in the quote (`SourceStore`), checks every applicable identity, re-reads only the figures the diagnosis names (without showing the values the identities imply, which a model could copy), and abstains on what it cannot settle. A prior-year column passes provenance and is caught by the identities; a typo or an invented line fails provenance. `llm_extractor` wraps any model client. Example 10; tests with scripted extractors on verbatim Apple 10-K lines. The runtime's reflection now checks every identity a JSON answer allows and passes the diagnosis to the model. New pages: `docs/agents.md` (what each agent does and does not do) and `docs/agent-workflows.md` (extraction with repair, implemented; covenant monitoring, answers with evidence and a committee ladder, designed, each with its evaluation plan).
- Multi-period covenant paths (`core/covenant_paths.py`): interest linked to each year's opening debt, scheduled amortisation, an excess cash sweep (fixed or by leverage grid), covenants each year (net leverage with step-downs, interest coverage, minimum liquidity). `simulate_covenant_path` (exact arithmetic, the reference), `check_covenant_path` (Z3: does any EBITDA path within yearly ranges, at any rate in a range, breach in any year; counterexamples replayed in plain arithmetic), `minimum_upfront_repayment_for_path` (counterexample-guided exact optimum, falling back to bisection on a quantified formula). With a leverage-based sweep the corners of the ranges can all comply while a path between them breaches (Tutorial 01 Step 4c). Each call uses a fresh Z3 context, so results and run time do not depend on earlier solver use (the same problem took 9 s alone and 53 s after other Z3 work). MCP tools `check_covenant_path`, `find_minimum_upfront_repayment_for_path`.
- Z3 beyond point checks (`core/invariants.py`): `diagnose_identities` finds the smallest sets of figures that would explain every failed accounting identity, with the values they would need (MaxSMT; minimal hitting sets of the conflicts, Reiter 1987), and lists every candidate when the identities cannot tell them apart; `minimum_debt_repayment` gives the exact smallest repayment meeting net-leverage and interest-coverage covenants together under a stated model; `check_covenants_over_ranges` decides whether both covenants hold for every input within given ranges, or returns a breaching combination. `SMTBalanceGate` puts the diagnosis into the reflection prompt. MCP tools `diagnose_accounting_identities` (corporate filings), `find_minimum_debt_repayment` and `check_covenants_over_ranges` (fixed income). Reference tests against closed forms, the worst-corner rule and hand-solved cases on Apple's 10-K figures. Tutorial 01 Step 4b, Tutorial 08 Step 3c.
- Validation status as data: `lilavati.validation_status` lists every engine with one status (reference-checked, piloted on real data, rule-based, not reference-checked), its validation page and open items. Every MCP tool result now has a `validation` field from it (input schemas unchanged), so an agent can tell a checked engine from an unchecked one. `docs/validation/status.md` and the pillar table on the docs home page are generated from it (`scripts/render_validation_status.py`); tests check that it covers exactly the registered tools, that the generated pages are current, and that README rows for unchecked or piloted engines say so (the order-book and statement-graph rows did not). New validation page for execution and portfolio: the Almgren-Chriss checks against the paper (previously only in the changelog), and what is and is not checked for the order book, Black-Litterman and HRP. Prompted by an outside review (2026-11-25); its decisions are recorded in `TODO.md`.
- `SourceStore` (`lilavati.core.provenance`) and `ProvenanceGate(store)`: citations are resolved against the sources a pipeline read (SEC company facts, PDF or HTML pages, Ind AS disclosures), checking hash, tag, period, filing date, page snippet and value. Without a store the gate checks only the form, as before. Registration helpers `PDF10KParser.register_in` and `india_filings.register_disclosure`; `record_hash` is the one canonical hash for XBRL fact records. Tutorial 08 Step 3b.

## [0.2.0] - release candidate (not yet tagged; see docs/releases/v0.2.0.md)
### Fixed
- Beneish M-score used wrong coefficients (TATA 4.037 → 4.679; LVGI +0.0327 → −0.327, per Beneish 1999). Scores quoted in docs refreshed.
- Almgren-Chriss schedule: clipping bug made very risk-averse schedules hold all shares to the end; volatility now in price units; discrete-time solution with η̃ = η − γτ/2; adds expected cost and variance (removes a stray 0.5 factor in variance).
- Merton solver could return non-solutions (equation errors up to 90%) for distressed / long-horizon inputs; now a bracketed 1-D solve with a residual check. Invalid inputs raise `ValueError`.
- Derivatives: SABR near-ATM skew term dropped (now matches QuantLib to ~1e-12); `calibrate_sabr` failed for index-level forwards; `is_arbitrage_free` was only an RMSE test (now checks butterfly and call-spread arbitrage of fitted prices); butterfly check depended on strike order; CRR tree silently mispriced when the up-probability left [0, 1]; non-finite / degenerate inputs now raise `ValueError`.
- Covenant check reported a false breach for ratios exactly at the limit (float rounding); non-finite inputs to invariant checks now raise a clear error.
- SLB covenant could report a missed target when met exactly (float rounding); WACI rejects zero-sum / negative weights; `total_carbon_footprint` relabelled (not PCAF financed emissions).
- Econometrics: GARCH p/q were passed to `arch` swapped (GARCH(1,2) returned α₂ = 0); OU half-life used the ln2/(1−φ) shortcut (27% high at φ = e^−0.5), now −ln2/ln φ; unconverged GARCH fits raise instead of returning start values; collinear/constant/non-finite inputs and invalid significance levels raise. Example/tutorial half-lives refreshed (2.74 → 2.38 days).
- Financial ML: fractional-d search returned a placeholder d*=1.0, p=1.0 when nothing qualified (now raises); ignored the caller's target p-value at d=0; float grid could exceed 1.0; d* rounded below step precision; exact barrier touches missed through float rounding; invalid inputs (NaN, zero/negative prices or horizon) now raise.
- LLM client: Gemini and Anthropic paths accepted `tools` but never sent them or parsed tool calls, so agents never used tools on those providers. Now implemented (Gemini functionDeclarations / functionCall / functionResponse incl. thoughtSignature echo and schema sanitising; Anthropic tool_use / tool_result with role merging). Bounded retries with backoff on 429/5xx/timeouts (`ModelSpec.max_retries`).
- Agent runtime: `max_reflection_iterations` also capped tool rounds, so multi-step tool plans ended with an empty answer while reporting success; now a separate `max_tool_rounds` and an `AgentOutput.completed` flag. Tool errors are flagged to the model (`is_error`).
- `run_llm_baseline.py --resume` re-ran unparsable answers as well as provider errors, re-rolling model failures and inflating scores; it now re-runs only errors and empty replies. Each record now stores the model's `finish_reason`, and summaries count `truncated` replies separately.
- `run_llm_baseline.py` scored answers unparsable when a model's inline `<think>` reasoning contained braces (2 `qwen3.6-27b` answers); reasoning blocks are now stripped first. New `--rescore` re-scores stored replies without API calls.
- Benchmark: generated case ids collided across set sizes (`generate_cases(2026, 2)` and `(2026, 4)` both had `GEN-T2-000`, different bonds); ids now carry seed and size (`GEN-S2026-N4-T2-000`), cases have a content hash (`case_content_hash`), and old ids resolve via `legacy_case_id`. Generated content is unchanged.
- Benchmark prompt: the `bond_price` key said "price of the 5-year bond" for generated bonds of 2-10 years (gpt-oss-120b priced a 10-year bond as 5-year); prompt v3 fixes it and every record stores `prompt_version`.
- Ollama preset pointed at the server root instead of its OpenAI-compatible `/v1` endpoint.
- `case_content_hash` included expected answer values, whose last digits depend on the platform's math library, so hashes differed between macOS and Linux CI; it now hashes only the question (scheme v2), and stored hashes were recomputed by `scripts/migrate_case_hashes.py` without changing any other field.
- `paired_difference` ordered pairs by content hash, so the seeded bootstrap CI changed when the hash scheme did; pairs are now ordered by case id (published Qwen3.8 bounds moved from +0.1083/+0.6875 to +0.1125/+0.6917; bootstrap Monte Carlo error is about ±0.01).
